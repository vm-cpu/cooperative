# Реєстр: перша ітерація

Прототип для #7, кроки B1–B2, C2, C4–C5. Використовує тільки 26 вигаданих боксів і 8 вигаданих власників. Числа не є статистикою кооперативу.

## Реалізація

- Гаражі, власники, ряди, якість даних; пов'язані картки.
- Пошук, комбіновані фільтри, природне сортування, скидання, порожній стан.
- Стабільні ID, незмінні поля source, текстові номери. Тезки не зливаються.
- Світла тема замінює стартовий перемикач тем згідно зі звуженим завданням. Великий текст і кнопка збільшення.
- Пошук і фільтри зберігаються в URL; позиція і фокус списку зберігаються в межах вкладки при переходах між картками.
- Реєстр лише для перегляду. Немає нових API, імпорту, міграцій, кешування персональних даних або запису у D1/R2.

## Перевірки

`npm run check`: 15 тестів, lint, форматування, dry-run staging/production. Dry-run нічого не публікує.

`npm run test:e2e`: Playwright перевіряє 320/375/768/1280 px, переходи, фільтри після повернення і перезавантаження, порожній результат, повторне завантаження після помилки та axe на чотирьох розділах. Тести інтерфейсу використовують статичний HTTP-сервер; Worker перевіряється окремими Vitest тестами. Скриншоти — артефакт GitHub Actions `registry-browser-results`.

Локальний запуск Chromium заблокований середовищем: `socket() failed: Operation not permitted`. Результат браузерних перевірок необхідно перевірити у CI. Ручні 200% zoom, TalkBack/VoiceOver, реальний телефон і авторизований staging ще потребують перевірки; не вважати їх пройденими автоматично.

## Сценарій для перевірки

1. Гаражі → пошук `1-01` → картка → власник → інший його гараж → повернення до списку.
2. Перевірити збереження запиту, фільтрів і позиції. Оновити сторінку.
3. Перевірити ряд 3 + «Без власника» + «Технічні бокси», потім скинути.
4. Власники → «Кілька гаражів»; знайти тезок і переконатися, що їхні картки різні.
5. Ряди → відфільтрований список; Якість даних → повтори/пропуски.
6. Збільшити текст, пройти клавішею Tab, перевірити 200% zoom і екранний читач.
7. На staging перевірити вихід і повторний вхід через Cloudflare.

## Відкриті питання та обмеження

- Співвласність, історія переоформлення, остаточні типи боксів — окреме узгодження.
- Фізичний план додамо після отримання перевіреної схеми.
- Приватний документ переглянуто тільки локально для структури: є багатоколонкові таблиці та повтори рядків; дані з нього не копіювалися в прототип.
- Реальний імпорт, ролі, контакти, документи і платежі не входять у цей PR.
- Staging: https://cooperative-staging.vm-55d.workers.dev. Публікація потребує авторизованого Wrangler; наявний MCP-доступ був наданий лише на читання. Production не змінювати.
