# Кооператив: опис проєкту

> Джерело: розмова з головою кооперативу (аудіо, 9:22, розпізнане автоматично).
> Документ описує потреби та план; уточнення позначені як відкриті питання.

## 1. Контекст

- **Хто:** гаражно-будівельний кооператив (ГБК), неприбуткова організація.
- **Масштаб:** ~570 гаражів (боксів).
- **Команда:** голова, бухгалтер, сторожі.
- **Як зараз:** увесь облік паперовий — книги («талмуди»), записи дублюються у двох книгах, чеки виписуються вручну. Частина внесків — готівкою, частина — банківським переказом.
- **Головна проблема:** щоб дізнатися, хто власник гаража і чи є борг, голова дзвонить бухгалтеру, а та шукає в паперах. Розсилка повідомлень — поштою, повільно й дорого.

## 2. Мета

Єдина електронна база кооперативу: карта гаражів, картка кожного гаража з власником, документами, платежами та боргом, звіти й розсилки — щоб відмовитись від ручної роботи з паперами.

## 3. Користувачі та ролі

| Роль          | Що робить                                                                           | Доступ                           |
| ------------- | ----------------------------------------------------------------------------------- | -------------------------------- |
| **Бухгалтер** | Основний користувач: вносить і редагує дані, приймає платежі, оформлює нових членів | Повний (читання + запис)         |
| **Голова**    | Контролює стан кооперативу, з грошима напряму не працює                             | Повний перегляд (тільки читання) |

Інших користувачів на старті немає. Вхід — за логіном і паролем.

## 4. Функціональні вимоги

### 4.1 Карта гаражів

- План території з пронумерованими гаражами (за рядами).
- Клік на гараж → відкривається його картка.
- Пошук за номером гаража, прізвищем власника, рядом/розташуванням.

### 4.2 Картка гаража

- Номер, ряд, розташування.
- Власник (член кооперативу): ПІБ, телефон, email, месенджер.
- Скани документів (право власності, заяви тощо).
- Історія платежів: дата, сума, спосіб (готівка / банк), за що.
- Поточний борг (є / немає, сума).
- Показники лічильника електроенергії та дати їх подання.

### 4.3 Платежі та внески

- Щомісячний членський внесок (розподіляється на податки, зарплати: сторожі, бухгалтер, голова).
- Вступний внесок для нового члена.
- Бухгалтер вносить платіж → він одразу видно в картці гаража.
- Електронна квитанція замість ручного чека.

### 4.4 Звіти

- Заборгованість по кооперативу за період (наприклад, за останній рік): кількість боржників, суми, список.
- Фільтри за сумою боргу, періодом, рядом.

### 4.5 Розсилки

- Вибрати групу (наприклад, усі боржники з боргом понад N грн) → надіслати попередження.
- Загальні оголошення всім (ремонт, збори тощо).
- Канали: месенджери (Viber / Telegram), SMS, email — замість паперової пошти.

### 4.6 Зміна власника (переоформлення)

1. Продавець отримує у бухгалтера довідку про відсутність боргу.
2. Новий власник приносить пакет документів.
3. Сплачує вступний внесок.
4. Бухгалтер оновлює картку гаража; історія попереднього власника зберігається.

## 5. Формат: PWA на телефон

Застосунок — **PWA (Progressive Web App)**: відкривається за посиланням, встановлюється на головний екран телефона як звичайна програма, без App Store / Google Play.

- Основний пристрій — **телефон** (mobile-first); на планшеті й комп'ютері теж працює.
- Іконка на головному екрані, відкривається на весь екран без адресного рядка.
- Оновлення приходять автоматично, нічого перевстановлювати не треба.
- Камера телефона — для фото документів прямо з картки гаража.
- Робота при поганому інтернеті на території: останні переглянуті дані доступні офлайн, внесені зміни відправляються, коли з'явиться зв'язок.

## 6. Доступність (accessibility)

Основний користувач — **бухгалтер, літня пані**. Тому простота й зручність — головна вимога до інтерфейсу, а не додаткова.

**Читабельність**

- Великий базовий шрифт (від 18–20 px), можливість збільшити ще (кнопка «А+»), повага до системного розміру шрифту телефона.
- Високий контраст тексту (WCAG AA, бажано AAA), без сірого тексту на сірому фоні.
- Світла тема за замовчуванням.

**Керування**

- Великі кнопки й зони натискання (не менше 48×48 px), достатні відступи між ними.
- Кнопки з текстом, а не лише іконками («Додати платіж», а не «+»).
- Без жестів-сюрпризів (свайпи, довге натискання) як єдиного способу дії.

**Простота**

- Мінімум кроків для щоденних дій: знайти гараж → внести платіж.
- Один екран — одна дія; зрозумілі слова без технічних термінів.
- Підтвердження перед важливими діями і можливість скасувати («Платіж збережено. Скасувати»).
- Помилки — простими словами з підказкою, що робити.
- Великий помітний пошук на головному екрані.

**Надійність**

- Нічого не губиться: автозбереження форм.
- Голосовий ввід (системна клавіатура телефона) — для пошуку й нотаток.
- Підтримка екранних читачів (TalkBack / VoiceOver): підписи до кнопок і полів.

**Перевірка:** перед кожним етапом — тест з бухгалтером на її телефоні; що незрозуміло — спрощуємо.

## 7. План робіт

### Етап 0 — Оцифрування (бухгалтер, паралельно з розробкою)

- [ ] Відсканувати / сфотографувати план розміщення гаражів.
- [ ] Відсканувати список членів кооперативу (по рядах, гараж за гаражем).
- [ ] Узгодити формат: одна папка / файл на гараж, назва = номер гаража.
- Платіжну історію на цьому етапі **не** переносимо.

### Етап 1 — MVP: карта і довідник (перша версія)

- [ ] PWA-основа: встановлення на телефон, іконка, офлайн-кеш.
- [ ] Дизайн-система з урахуванням доступності (шрифти, контраст, великі кнопки).
- [ ] Вхід за логіном для двох ролей (бухгалтер, голова); бухгалтер залишається залогіненою на своєму телефоні.
- [ ] База гаражів і членів (Cloudflare D1).
- [ ] Схема/карта гаражів з пошуком за номером і прізвищем.
- [ ] Картка гаража: власник, контакти, скани документів (Cloudflare R2).
- [ ] Імпорт даних з етапу 0.
- **Результат:** голова бачить відкритий гараж → за хвилину знає, чий він і як зв'язатися.

### Етап 2 — Платежі та борги

- [ ] Внесення платежів (готівка / банк), історія в картці.
- [ ] Нарахування щомісячних внесків, розрахунок боргу.
- [ ] Показники лічильників.
- [ ] Звіт про заборгованість за період.
- [ ] Перенесення поточних боргів з паперових книг.

### Етап 3 — Розсилки

- [ ] Вибір групи отримувачів за фільтрами.
- [ ] Відправка в месенджер / SMS / email, журнал відправлених повідомлень.

### Етап 4 — Процеси й документи

- [ ] Переоформлення гаража (довідка про відсутність боргу, вступний внесок).
- [ ] Електронні квитанції.
- [ ] Експорт звітів (PDF / Excel) для податкової та зборів.

## 8. Технічна база

- **Клієнт:** PWA (manifest + service worker), mobile-first.
- **Хостинг:** Cloudflare Workers (проєкт `cooperative`), автодеплой з гілки `main` репозиторію `vm-cpu/cooperative`.
- **Дані:** Cloudflare D1 (SQL) — гаражі, члени, платежі, борги.
- **Файли:** Cloudflare R2 — скани документів, план території.
- **Безпека:** персональні дані членів кооперативу → тільки авторизований доступ, резервні копії бази.

## 9. Відкриті питання

1. **Ліцензійність ПЗ:** чи є вимоги до юридичної особи щодо програм обліку (власна розробка замість 1С тощо)? Що може запитати податкова при перевірці?
2. **Паперовий облік:** чи потрібно паралельно вести паперові книги, і як довго?
3. **Карта:** є готовий план території (схема) чи будуємо по рядах вручну? Потрібна прив'язка до Google Maps?
4. **Внески:** розмір щомісячного і вступного внесків, чи змінюються з часом, чи нараховується пеня?
5. **Лічильники:** які саме (електроенергія?), як часто подаються показники, як рахується оплата?
6. **Банківські платежі:** чи можна отримувати виписку з банку для автоматичного зіставлення платежів?
7. **Розсилки:** який месенджер основний у членів кооперативу (Viber / Telegram)?
8. **Персональні дані:** згода членів кооперативу на зберігання даних в електронній базі.
9. **Телефон бухгалтера:** яка модель / Android чи iPhone, який розмір шрифту стоїть у системі — під це тестуємо інтерфейс.
